# 向量化记录：做了什么、等价性到什么程度、速度多少

> 原则（用户定的规矩）：**没等价性就是失败**。所以每一项都必须先给出「等价到什么程度」的**机器可验证断言**，
> 再给速度数字；两个都过了才允许进默认实现。
>
> 速度一律用**同输入、预热后 3 次平均**测得（首次调用含分配/编译开销，冷启动数字会误导 2–10 倍 ✗）。

## 二、`decay_linear`：为什么「只能到 ≤1 ulp」

加权和是**浮点加法**：原实现用 `rolling().apply(lambda w: np.sum(w*weights))`（numpy 的 pairwise 求和顺序），
向量化必须按 `Σ_k coef[k]·x[t−k]` 的顺序累加 ⇒ **求和顺序不同 ⇒ 末位必然可能不同** ✗。
这是 IEEE-754 的性质，不是实现瑕疵；要彻底消除只能逐位复刻 numpy 的 pairwise 分块求和（复杂、且抵消掉大部分收益）。

所以验收标准是**可验证的边界**，不是口头承诺：

* `tests/test_decay_equivalence.py` 断言：**NaN 掩码逐位相同** + `max|Δ| ≤ 1e-13` + `rel ≤ 1e-15`；
* 覆盖 `order{recent_first, oldest_first} × dense{False,True} × window{3,5,10,20} × {常规, 30% NaN, 并列值}` 共 96 例；
* **golden 快照按此重新生成**（该 1 ulp 变化会触发位级守卫，属预期）。

### 一个真实的教训

我第一版向量化把**系数方向写反了**（`recent_first` 的新值应权重最大），差异高达 **40** ✗ ——
被等价性测试**当场抓出**（不是靠肉眼看公式）。这条说明：**等价性测试的价值在于抓「语义写反」，
而不只是抓末位**。

## 三、`ts_argmax` / `ts_argmin`：为什么能做到「逐位精确」

输出是**整数索引**（1-based 自窗口起点，或 `days_ago`），不涉及浮点累加 ⇒ 只要逻辑一致就完全相等。

实现：`rolling.max/min`（向量化）+ 自新到老扫一遍、**命中即覆盖** ⇒ 最老命中者胜出，
正好复刻 `np.argmax`/`np.argmin` 的**并列取最早**规则；`min_periods=window` ⇒ 窗口含 NaN 时极值 NaN ⇒ 结果 NaN。

验收：`tests/test_arg_equivalence.py` 用 `np.array_equal` **精确**断言（40 例），
含「全等窗口 ⇒ `days_ago = w−1`」的并列规则专项；**golden 与 101 因子全量无需重生成**（313 passed）——
这本身就是逐位不变的独立证据。

## 四、`product`：为什么**不做**

1. `exp(Σ log)` 只对**正数**成立：遇 **0** ⇒ `log(0)=−inf`；**负数** ⇒ NaN —— 而价格/成交量里零和负数都真实存在；
2. **上溢行为不同**：连乘可能提前溢出为 `inf`，`exp(求和)` 的溢出点与顺序都不同 ⇒ 差异可能是**数量级**，不是 1 ulp；
3. 「累乘 + 相除」方案会引入 0/NaN 传播与相消误差。

按「没等价性就是失败」的规矩，**保持 apply 实现**（用它的因子很少，收益不抵风险）。

## 五、边界（哪些不属于上游）

* **并行**（按因子/按日期切多进程）、分块、断点续跑、缓存 —— 属**使用者的数据仓库**，不进库（库是无状态、单面板的）；
* 口径选择（`dense` 等）属研究决定，但**入口在库**（见 `docs/audit_2026-10-18.md` 的 B4）。

> 一句话：**单核常数因子归上游（且必须给等价性断言），多核与状态归本地。**
