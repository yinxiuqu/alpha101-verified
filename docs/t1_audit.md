# A 股 T+1 审计：101 个因子里有没有「只符合美股 T+0」的东西？

**结论（先说）**：**没有**。101 条公式全部是对**日频行情**做的代数/时序/截面变换，
**不包含任何「当日买入当日卖出」的要求**；T+1 只约束**执行**，而本仓库**没有执行层**
（设计文档 §7.1 非目标：不做回测/选股）。因此 T+0 与 T+1 的分歧**不落在因子计算里**，
而落在一个使用者必须自己处理的地方——**信号与成交的时滞**。下面把两件事分开说清楚。

## 一、结构性证据（因子层不含执行假设）

| 检查 | 结果 |
|---|---|
| `src/` 里是否有回测/成交/持仓层 | **没有**（`src/alpha101v/` 只有算子、因子、面板适配器、注册表；无下单、无持仓、无撮合） |
| 因子输入 | 全部是**当日已收盘或已发生的行情**（`close`/`open`/`high`/`low`/`vwap`/`volume`/`amount`/`returns`/`cap`），**没有分钟级、没有盘中快照、没有买卖盘口** |
| 是否含前视（T+1 正确性的前提） | ✅ 无：101 个因子全部通过**时间截断一致性**测试（截断面板重算 = 逐点相等，`tests/test_factors_all.py`） |
| 是否用到未来收益 | ✅ 无：因子层只用当日与历史；未来收益只在评估工具里出现（见下） |

## 二、唯一真正与 T+1 相关的地方：前瞻收益的 horizon

评估工具（`tools/l6_statistics.py`，**明文不参与 verified/partial 判定**）计算 IC 用的是：

```python
HORIZONS = (1, 2, 3, 5, 10)                 # 交易日
return close.shift(-horizon) / close - 1.0  # t → t+h 的收盘到收盘收益
```

* **没有任何 h=0 路径** ✅ —— 也就是说，工具里不存在「当日买入、当日卖出」这种在 A 股被 T+1 禁止的往返；
* h≥1 的收盘到收盘收益在 A 股**是可执行的**（t 日收盘买入 → t+1 日及以后收盘卖出 ✓ T+1 满足），
  前提是你接受「以收盘价成交」这一约定（见下一节）。

## 三、使用者必须自己处理的三件事（本仓库**不**替你做）

1. **信号时滞**：因子值在 t 日收盘后才有 ⇒ 严格做法是 **t+1 开盘或 t+1 收盘成交**，而不是 t 日收盘成交。
   本仓库的评估工具用的是「t 日收盘信号 → t+h 收盘收益」，等价于假设**能在收盘竞价里按收盘价成交**。
   这在 A 股**制度上可行**（有收盘集合竞价），但需要你在实时环境里算得出来；批量离线计算则应整体后移一天。
2. **涨跌停与停牌**：一字板买不进、跌停卖不出、停牌不能交易 —— 本仓库**完全不建模**（没有执行层）。
   任何基于这些因子的实盘/回测都必须自行剔除不可成交的样本。
3. **T+1 的持仓约束**：当日买入的股票当日不可卖出 ⇒ 若你的策略依赖「日内对冲/日内平仓」，
   那不是这些因子的问题，而是策略形态在 A 股不成立。本仓库的因子都是**日频信号**，天然是「持仓过夜」型的。

## 四、那 43 个用 `vwap`、34 个用 `high`、33 个用 `low` 的因子算不算 T+0 ？

不算。它们用的是**当日已实现的**最高/最低/成交均价 —— 这些在收盘后就是确定的历史数据，
与「当日能不能买卖」无关。它们只是**形态描述**（收盘在当日区间的位置、收盘与成交均价的偏离等）。

真正需要注意的是**经济含义**：一部分因子（例如 `alpha101` 这种 `(close - open)/(high - low)`、
`alpha2` 这种 `(close - open)/open`）描述的是**日内反转/动量**。在 A 股 T+1 下，
你只能在**次日**表达这个观点 ⇒ 日内已完成的那部分价格变动你吃不到，
**因子本身没有任何问题，但它对应的收益会打折**。这属于「策略与制度」的交互，
不是实现缺陷 —— 也正是本仓库把「投资表现」列为非目标的原因（设计文档 §7.1）。

## 五、一句话总结

* **因子计算**：与 T+0/T+1 **无关**，101 条全部是日频变换，且无前视 ✅；
* **评估工具**：只用 h≥1 的前瞻收益，**无当日往返** ✅；
* **执行/回测**：本仓库不做；你要做的话，必须自己加上「信号后移一天 + 剔除涨跌停/停牌」这道工序。
